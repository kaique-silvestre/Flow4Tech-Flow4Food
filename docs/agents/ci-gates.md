# CI gates e testes (detalhe)

Detalhe de referencia, lido sob demanda a partir do indice em `CLAUDE.md`. Mantenha aqui o detalhe do tema; a raiz guarda so o que vale para todo agente.

## CI gates (`.github/workflows/ci.yml`, GitHub Actions)
One pipeline on every pull request and on every push to `dev-v2`, `main-v2` and `main` (a direct push to `dev-v2` is allowed and runs the same gates; `main-v2` only receives PRs and runs them again on the merge commit). Merge requires the aggregate job `gates` to be green (branch protection); Deploys are Railway's, not a job here.
- `build`: `dotnet build -c Release` + `dotnet format --verify-no-changes`
- `typecheck-frontend`: `pnpm install --frozen-lockfile && pnpm -r typecheck`
- `coverage-back` (informational, not in `gates`): every back test job collects Cobertura with coverlet and uploads it; this job merges them with ReportGenerator into the run summary and the `coverage-back-merged` artifact. No floor yet (F4-0104).
- `lint-frontend`: `pnpm lint` (Biome 2.6.3 pinned exact: lint + format + import order + a11y rules). Errors fail, warnings and infos do not. Two a11y rules are relaxed in `biome.jsonc` with the reason (F4-0099; follow-up F4-0100).
- `architecture-frontend` (F4-0114, in `gates`): `pnpm arch:front` runs dependency-cruiser 18.7.2 (pinned exact) with `.dependency-cruiser.cjs` over `frontend/{app,control,design-system,packages/api-client}`: no file cycles; `design-system`/`api-client` never import `app`/`control`; `app` and `control` never import each other; `api-client` does not know the UI; `features/*` never import `router`/`main`/`Shell`; `features/sessao` is the base and imports no other feature; production code imports no test file and no devDependency (type-only `.d.ts` and peer deps excepted); every npm import is declared and every import resolves (`virtual:` modules excepted). Each rule was checked by planting a violation and seeing it fail. An exception goes in the rule's `from.pathNot`/`to.pathNot` with the reason beside it, never by turning the rule off. Also runs in `pre-push`. The mirror of `backend/tests/Architecture`.
- Stubs de rede tipados pelo contrato (F4-0116, sem job proprio: roda no `typecheck-frontend`): `jsonDoContrato(metodo, rota, status, corpo)` em `frontend/app/src/test-utils.tsx` exige que o corpo seja exatamente o que `schema.ts` declara para aquela rota e status; renomear ou mudar o tipo de um campo na API quebra o `pnpm -r typecheck` nos testes em vez de passar um mock que a API real nao satisfaz. A rota e o template do contrato (`"/comandas/{comandaId}/pagamentos"`), nao o caminho que o `stubRede` casa. Use `json()` simples so para o que o contrato nao tipa (corpo vazio, falha de rede, resposta malformada de proposito) e para os testes de tela fora de pagamento/fila/caixa que ainda nao foram convertidos. Fabricas de teste (`conta`, `pagamento`, `turno`, `comandaJson`) sao tipadas com `components["schemas"][...]`. Cada conversao foi provada plantando um campo errado. A primeira passada achou um stub de cancelamento sem o `item` que o contrato exige.
- `dead-code-frontend` (F4-0115, in `gates`): `pnpm dead:front` runs Knip 6.45.1 (pinned exact, `knip.jsonc`) over the four front workspaces and fails on an unused file, export, exported type or dependency, an undeclared dependency or an unresolved import. Complements `architecture-frontend` (that one checks the edges that exist, this one what has none). An export used only inside its own file loses the `export`; a dead function is deleted. An exception goes in `knip.jsonc` with the reason beside it (today: `typecheck` script seen as a binary, `@flow4tech/design-system` in the empty `control`, the font imported by CSS, the generated `schema.ts`). Also runs in `pre-push`. First run found 1 dead file (`app/src/api.ts`) and 14 exports used only locally.
- `unit-tests`: `Flow4Tech.Tests` excluding classes whose name contains `Endpoints` or `Integration`
- `integration-tests`: those classes, with real PostgreSQL (Testcontainers `postgres:17-alpine`). Name new integration test classes `*Endpoints*` or `*Integration*` or they run as unit tests.
- `architecture-tests`: `backend/tests/Architecture`
- `secret-scan`: gitleaks over full git history (`fetch-depth: 0`)
- `codeql`: SAST (C#, JS/TS) only while the repo is public; skipped when private (`gates` accepts `skipped`), then switch to Semgrep, see `docs/runbooks/sast.md` (F4-0086).
- `trivy`: `trivy config` (Dockerfile, compose) and `trivy image` of the deployed image, HIGH/CRITICAL, fixable only; exceptions in `.trivyignore` with reason and expiry (F4-0087, `docs/runbooks/sast.md`).
- `dast`: OWASP ZAP API scan in safe mode (passive) against the compose API using `backend/src/Api/openapi.json`; warnings do not block, report kept as artifact `zap-report` (F4-0093, `docs/runbooks/sast.md`).
- Security headers: every API response goes through `SecurityHeadersMiddleware` (`Api/SecurityHeaders.cs`: nosniff, CSP `default-src 'none'`, DENY, no-referrer, no-store, HSTS only over HTTPS); front headers live in `frontend/{app,control}/vercel.json` (F4-0094; full front CSP pending, F4-0095).
- Every GitHub Action in `.github/workflows` is pinned by full commit SHA with the tag in a comment; never `@v4` (F4-0091, procedure in `docs/runbooks/sast.md`).
- `dependency-audit`: `dotnet list package --vulnerable --include-transitive` and `pnpm audit --audit-level=high`
- `openapi-contract`: regenerates `openapi.json` + client and fails if the committed output differs (`git diff --exit-code`); runs client tests; runs `oasdiff breaking --fail-on ERR` (pinned `tufin/oasdiff` image) between the base revision (PR base / push `before`) and the head contract, so removing or narrowing anything clients rely on fails the PR.
- `frontend-tests`: `pnpm -r --if-present test:coverage` (vitest with coverage; each package's `vitest.config.ts`/`vite.config.ts` has a FLOOR in `coverage.thresholds`, the build fails below it; raise it when the real number rises; `coverage-front` artifact; F4-0103). `frontend-e2e`: Playwright at 390x844 and 360x740 against the real API from `docker compose` plus the documented seed; screenshots kept as an artifact. `e2e/acessibilidade.spec.ts` (F4-0109, `@axe-core/playwright` 4.14.0) scans sign-in, comandas and caixa in light and dark with axe-core (WCAG 2.1 A/AA) and FAILS on any violation (`AXE_REPORT_ONLY=1` only reports while a new screen is being fixed); JSON per screen in the `e2e-axe` artifact. A new screen needs a scan there. Axe finds about a third of the real accessibility problems (no keyboard-flow or screen-reader judgement).
- Property tests (F4-0105, FsCheck.Xunit 3.6.0): `SalaoPropertyTests` (Flow4Tech.Tests), `PolicyPropertyTests` (Authorization), `IdentidadePropertyTests`, `AuditPropertyTests`, `ConfiguracaoPropertyTests`. Pure rules, no Docker, run in the same jobs as their project's unit tests. Generators go in a `*Geradores` static class (`[Property(Arbitrary = [typeof(...)])]`); a failure prints the shrunk counterexample. Each property was checked by planting a bug in the rule (mutation by hand) and seeing it fail. A bill-splitting function does not exist yet (F4-0061): add its properties (parts sum to total, difference at most 1 cent) when it lands.
- `mutation-tests` (in `gates` since F4-0107; floors in each `stryker-*.json` under `thresholds.break`: Permissoes 70, Organizacao 72, Comandas 64, Caixa 90, Cardapio 95, Pagamentos 95; Identidade has NO floor, its score of 36.6% misses code that only the Docker tests reach; raise a floor when the score rises, never lower it without a reason in the commit; F4-0106): Stryker.NET 5.0.0 (`.config/dotnet-tools.json`, `dotnet tool restore`) plants bugs in the pure domain code and reports how many the no-Docker tests catch. One `stryker-*.json` per domain in the test project that references it (`backend/tests/{Authorization,Identidade,Organizacao,Flow4Tech.Tests}`); run locally with `cd backend/tests/<proj> && dotnet tool run dotnet-stryker -f <config>` (1 to 2 min each). Survivors worth fixing are real rule gaps; guard clauses (`ThrowIfNull`) and reason strings are expected noise. Baseline from the first CI run (no-Docker tests only; low scores with many NoCoverage are code that only the Docker tests reach): Pagamentos 100%, Cardapio 100% and Caixa 95.2% (1 equivalent mutant) after boundary tests, Organizacao 77.8% (only ThrowIfNull guards left), Permissoes 75.9%, Comandas 69.2% (its 2 survivors are an equivalent mutant and a ThrowIfNull), Identidade 36.6% (78 NoCoverage). The CI run shows the numbers before these tests for Caixa/Organizacao/Cardapio. Back line coverage of all projects merged: 93.3% lines, 85.6% branches (F4-0104 can set the floor). No floor until the first CI runs.
- `bundle-budget` (F4-0110, in `gates`): builds the app and `frontend/scripts/bundle-budget.mjs` (`pnpm --filter @flow4tech/app bundle:check`) fails when the gzip size of the JS (total and largest file) or CSS exceeds `frontend/app/bundle-budget.json` (limits ~6% above the first measure: JS 187.8 kB of 200, CSS 5.0 kB of 8, in KiB; the JS limits went to 210 in F4-0055 because the table map screen took the app from 199.6 to 202.1 kB, the app having sat at 99.8% of the old limit). Raise a limit only with a reason in the commit; the real fix is route-level code splitting (the app ships ONE 179 kB gzip chunk, F4-0111 pending). The `control` front has no build yet, so no budget. Lighthouse (performance/PWA) is not wired in.
- `isolation-tests`: `backend/tests/Isolation` (tenant isolation + RLS architecture rule, real PostgreSQL via Testcontainers, app credential). Own project, so the `unit-tests`/`integration-tests` name filters (which target `Flow4Tech.Tests` only) neither run nor miss it.
- `outbox-tests`: `backend/tests/Outbox` (outbox atomicity, at-least-once dispatcher, idempotent consumer, organization context restored in background jobs under RLS; real PostgreSQL via Testcontainers). Own project, same reason as isolation.
- `audit-tests`: `backend/tests/Audit` (append-only privileges, hash chain, tamper detection with the OWNER credential, concurrent writers, secret rule, technical log; real PostgreSQL via Testcontainers). Own project, same reason as isolation.
- `identidade-tests`: `backend/tests/Identidade` (sessions, rotating refresh, reuse, revocation triggers and the access token, Argon2id vs the RFC 9106 vector, k-anonymity breach check, accounts, owner protection, login without enumeration, pre-authentication functions and the RLS exception, real PostgreSQL via Testcontainers). Own project, same reason as isolation.
- `organizacao-tests`: `backend/tests/Organizacao` (layered settings on real PostgreSQL via Testcontainers). Own project, same reason as isolation.
- `authorization-tests`: `backend/tests/Authorization` (engine contract on every engine, daily-cap concurrency under RLS on real PostgreSQL via Testcontainers, app credential). Own project, same reason as isolation.
- `architecture-tests` also runs the route permission gate (`RoutePermissionTests`, ticket 10): every route declares a catalog permission, unknown permission fails, catalog export `backend/permissions.catalog.txt` must match. It is the permission gate; there is no separate job.
- No secrets in the repo: config via environment variables; gitleaks fails the pipeline on any finding in history.

Duration budget (TARGET, not yet measured; replace with the first real run): whole pipeline <= 10 min wall clock, each job <= 5 min (integration <= 8 min). Local reference: build ~10 s, integration tests ~20 s with warm Docker.
