# Salao (fatia /salao)

Detalhe de referencia, lido sob demanda a partir do indice em `CLAUDE.md`. Mantenha aqui o detalhe do tema; a raiz guarda so o que vale para todo agente.

## Salão (fatia `/salao`, `.scratch/S-03-dominio-salao/`, ADR-014 e 015)
- Quatro módulos novos, cada um com Domain/Application/Infrastructure/Interface; arestas permitidas só estas: `Comandas -> Cardapio`, `Comandas -> Pagamentos`, `Pagamentos -> Caixa` (`backend/modules.dependencies.json`). Ninguém depende de `Comandas` (reage por eventos). Mesa mora em `Comandas`.
- Tabelas (migrações 0015 a 0020, todas tenant com RLS exata e FK composta): `categorias`, `produtos` (preço em centavos), `produtos_frequencia` (alimentada ao lançar), `turnos_caixa` (um turno aberto por unidade), `mesas`, `comanda_numeracao`, `comandas` (FK composta para `mesas` por `(organizacao_id, unidade_id, mesa_id)`), `rodadas`, `itens_comanda` (preço congelado no lançamento), `pagamentos`.
- Permissões (`[PermissionCatalog]` de cada módulo): `comanda:abrir|ver|ver-comandas-de-outros|lancar-item|cancelar-item|desfazer-rodada|receber-pagamento|fechar|remover-taxa-servico`, `caixa:abrir|fechar|ver|ver-todos`, `mesa:ver|gerenciar`, `produto:ver|gerenciar`, `pagamento:registrar|ver`. Ações de auditoria: `comanda:abrir|lancar-rodada|cancelar-item|desfazer-rodada|fechar|remover-taxa-servico`, `pagamento:registrar`, `caixa:abrir|fechar`, `mesa:criar`, `produto:criar|alterar`. Eventos (outbox, mesma transação): `cardapio.produto-criado|produto-alterado|categoria-criada|categoria-alterada`, `comanda.aberta|rodada-enviada|rodada-desfeita|item-cancelado|fechada`, `pagamento.registrado`, `caixa.aberto|fechado`.
- Configurações (`[SettingsCatalog]`): `operacao.usar-mesas`, `venda.taxa-servico-percentual` (organização e unidade), `caixa.exigir-caixa-aberto`, `comanda.janela-desfazer-segundos` (só sistema, 8 s).
- Rotas (todas `.RequireSession()` + `.RequirePermission`): `GET|POST /cardapio/categorias`, `PUT /cardapio/categorias/{id}`, `GET|POST /cardapio/produtos`, `PUT /cardapio/produtos/{id}`, `GET /cardapio/produtos/busca|frequentes|gestao`, `GET|POST /mesas`, `GET|POST /caixa/turnos`, `GET /caixa/turnos/atual`, `POST /caixa/turnos/atual/fechar`, `GET|POST /comandas`, `GET /comandas/{id}/itens|conta|pagamentos`, `POST /comandas/{id}/rodadas`, `.../rodadas/{rodadaId}/desfazer`, `.../itens/{itemId}/cancelar`, `.../pagamentos`, `.../fechar`, `.../taxa-servico/remover`, `GET /sessao/permissoes` (as permissões do próprio chamador no salão; o app só ESCONDE o que o servidor recusaria).
- Concorrência e idempotência: toda escrita numa comanda leva a `versao` que a tela viu; `UPDATE ... SET versao = versao + 1 WHERE versao = @v AND estado = 'aberta'`; versão velha = 409 `versao-desatualizada` com `versaoAtual`. O id da rodada e o id do pagamento nascem no cliente (UUID v7): `INSERT ... ON CONFLICT DO NOTHING`, repetir devolve o gravado (200, sem novo efeito).
- Receber e fechar (`GestaoDoRecebimento`): uma unidade de trabalho com a decisão de permissão, o turno aberto (`caixa-fechado` 409 sem ele), o pagamento (troco calculado no servidor), a versão, a auditoria e o evento; o esperado do caixa é calculado em SQL no fechamento (fundo + recebido em dinheiro). Cancelar item, desfazer rodada e remover taxa são recusados (409 `valor-ja-recebido`) se a conta ficaria abaixo do já recebido. `fechar` só com saldo zero (409 `saldo-pendente`).
- Front do salão (`frontend/app`, PWA, Vite + React + TanStack Router/Query): `src/features/{sessao,entrar,conta,caixa,comandas,fila}`; cliente tipado `@flow4tech/api-client` (openapi-fetch); token de acesso só em memória, refresh por cookie `__Host-f4t_refresh`, um refresh por vez; fila de ações pendentes em `features/fila` (localStorage `f4.fila.v1`, ordem preservada, uma por vez, espera 2 s a 30 s, conflito de versão adotado na hora do envio, falha permanente fica visível; rodada e pagamento; só a conta que enfileirou envia; Sair limpa). Design system em `frontend/design-system` (tokens, componentes e testes vitest).
- Testes do front: `pnpm -r --if-present test` (vitest + testing-library); navegador: `E2E_API=1 pnpm --filter @flow4tech/app e2e` contra a API real e o seed (`docs/agents/project.md`), em 390x844 e 360x740, com as telas em `frontend/app/e2e-results/screenshots`. Dois tenants no salão: `DoisTenantsEndpointsTests` (fluxo completo em cada organização por HTTP + varredura de tabelas).
